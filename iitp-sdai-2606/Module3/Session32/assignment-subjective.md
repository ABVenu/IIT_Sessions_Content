# Subjective Assignment: Coding Club Lab Register

## Practical Task

**Difficulty:** Medium  
**Type:** Coding implementation (SQL)

---

## Scenario

A coding club keeps a lab register in PostgreSQL.

- One lab room can hold many members. Each member points at one room.
- One member can join many workshops, and one workshop can have many members. Those pairs sit in a third table.
- You will filter rows, correct saved values, remove one temporary member, and remove one signup without removing the person or the workshop.

Write one script that builds this register and checks it. Do not read two tables on the same result line. Each `SELECT` uses one table.

## Answer Explanation

### Walkthrough

1. Drop `signups` and `workshops` before `members`, and drop `members` before `rooms`, so no foreign key is left hanging.
2. Create the four tables. `signups` stores ids, and its primary key is the pair, so the same member-workshop pair cannot be inserted twice.
3. Seed three rooms, two workshops, and four members. Add `room_id` with `ALTER TABLE ... ADD COLUMN ... REFERENCES rooms (id)`, then insert the four signup pairs.
4. Part B uses the original scores and cities: `>= 80` keeps Neha (84) and Sara (93); `OR` keeps Sara and Dev; `AND` keeps Neha only.
5. Before any assignment, `room_id IS NULL` lists all four members. `= NULL` would not.
6. Four `UPDATE`s set the rooms. Neha and Arjun share room 1. That is one room, many members. The later `IS NULL` read is empty. `room_id = 1` returns Neha and Arjun only.
7. Dev’s score update touches id 4 only. Arjun’s update changes city and score together because both assignments sit in `SET`, separated by a comma, and the email finds his row.
8. The practice insert receives id 5. Deleting that email removes only that row. The next identity value is not 5. The remaining ids are 1–4. Spare Lab can then be deleted because nobody still stores `room_id` 3.
9. Arjun’s new signup is `(2, 1)`. Deleting `(1, 2)` leaves Neha in `members`, leaves Git Workshop in `workshops`, and leaves Neha’s SQL Basics pair. Workshop 1 then has member ids 1, 2, and 3. Neha’s remaining `workshop_id` is 1.

### Complete Code

```sql
DROP TABLE IF EXISTS signups;
DROP TABLE IF EXISTS workshops;
DROP TABLE IF EXISTS members;
DROP TABLE IF EXISTS rooms;

CREATE TABLE rooms (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    room_name TEXT NOT NULL UNIQUE
);

CREATE TABLE members (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    city TEXT DEFAULT 'Not given',
    score INTEGER NOT NULL CHECK (score >= 0 AND score <= 100)
);

CREATE TABLE workshops (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    workshop_name TEXT NOT NULL UNIQUE
);

CREATE TABLE signups (
    member_id INTEGER NOT NULL REFERENCES members (id),
    workshop_id INTEGER NOT NULL REFERENCES workshops (id),
    PRIMARY KEY (member_id, workshop_id)
);

INSERT INTO rooms (room_name)
VALUES
    ('Lab A'),
    ('Lab B'),
    ('Spare Lab');

INSERT INTO workshops (workshop_name)
VALUES
    ('SQL Basics'),
    ('Git Workshop');

INSERT INTO members (full_name, email, city, score)
VALUES
    ('Neha Shah', 'neha@example.com', 'Pune', 84),
    ('Arjun Das', 'arjun@example.com', 'Not given', 71),
    ('Sara Ali', 'sara@example.com', 'Chennai', 93),
    ('Dev Patel', 'dev@example.com', 'Lucknow', 66);

ALTER TABLE members
ADD COLUMN room_id INTEGER REFERENCES rooms (id);

INSERT INTO signups (member_id, workshop_id)
VALUES
    (1, 1),
    (1, 2),
    (3, 1),
    (4, 2);

SELECT full_name, score
FROM members
WHERE score >= 80
ORDER BY id;

SELECT full_name, city
FROM members
WHERE city = 'Chennai' OR city = 'Lucknow'
ORDER BY id;

SELECT full_name
FROM members
WHERE city = 'Pune' AND score >= 80;

SELECT full_name
FROM members
WHERE room_id IS NULL
ORDER BY id;

UPDATE members SET room_id = 1 WHERE id = 1;
UPDATE members SET room_id = 1 WHERE id = 2;
UPDATE members SET room_id = 2 WHERE id = 3;
UPDATE members SET room_id = 2 WHERE id = 4;

SELECT full_name
FROM members
WHERE room_id IS NULL;

SELECT full_name
FROM members
WHERE room_id = 1
ORDER BY id;

UPDATE members
SET score = 72
WHERE id = 4
RETURNING id, full_name, score;

UPDATE members
SET city = 'Jaipur', score = 75
WHERE email = 'arjun@example.com'
RETURNING id, full_name, city, score;

INSERT INTO members (full_name, email, city, score, room_id)
VALUES ('Practice Member', 'practice@example.com', 'Delhi', 50, 3);

DELETE FROM members
WHERE email = 'practice@example.com'
RETURNING id, full_name, email;

SELECT id, full_name
FROM members
ORDER BY id;

DELETE FROM rooms
WHERE id = 3;

INSERT INTO signups (member_id, workshop_id)
VALUES (2, 1);

-- Removes Neha's Git pair only; Neha and Git Workshop both stay.
DELETE FROM signups
WHERE member_id = 1 AND workshop_id = 2
RETURNING member_id, workshop_id;

SELECT member_id, workshop_id
FROM signups
WHERE workshop_id = 1
ORDER BY member_id;

SELECT workshop_id
FROM signups
WHERE member_id = 1;
```

### Alternative approaches

- `room_id` can be created with the `members` table and filled in the first `INSERT`, instead of `ALTER TABLE` plus later `UPDATE`s. The checks stay the same if the null read is done before those values are filled.
- Dev can be found by `email = 'dev@example.com'` instead of `id = 4`. Arjun can be found by `id = 2` instead of email. One column in `WHERE` is enough when it identifies the row you mean.
