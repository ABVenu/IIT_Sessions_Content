## Scenario

A music school stores rooms, trainees, skills, and bookings in separate tables. One room can hold many trainees. One trainee can book many skills.

Quiet Room has no trainee. Rhea Paul has no room. She also has no booking.

### Queries

1. Trainee name and room name, only where the trainee has a room. Use `INNER JOIN` from `trainees` to `rooms` on `room_id`. Order by trainee id.

```text
Kabir Sen | Practice Room A
Lata Nair | Practice Room A
```

2. Every trainee, and the room name when there is one. Use `LEFT JOIN` from `trainees`. Order by trainee id.

```text
Kabir Sen | Practice Room A
Lata Nair | Practice Room A
Rhea Paul | (NULL)
```

3. Trainee name beside skill name. Inner-join `bookings`, then inner-join `skills`. Give each join its own `ON`. Order by trainee id, then skill id.

```text
Kabir Sen | Scales
Kabir Sen | Chords
Lata Nair | Scales
```

4. Every trainee. Show `Chords` only when that trainee booked skill id 2. Put `b.skill_id = 2` in the `ON` of the `bookings` join, not in `WHERE`. Then left-join `skills`. Order by trainee id.

```text
Kabir Sen | Chords
Lata Nair | (NULL)
Rhea Paul | (NULL)
```

## Answer Explanation

### Walkthrough

1. The setup drops `bookings` first and `rooms` last, then inserts two rooms, three skills, three trainees, and three bookings.
2. The inner join on `t.room_id = r.id` returns Kabir and Lata. Rhea has no room, and Quiet Room has no trainee, so both stay out. Practice Room A appears twice because two trainees match it.
3. The left join keeps Rhea. Her room name is NULL.
4. The two inner joins walk trainee → booking → skill. Kabir’s two bookings become two result rows. Rhea and Sight Reading stay out.
5. In query 4, `b.skill_id = 2` sits inside `ON`, so it only chooses which booking may stick. Kabir shows Chords. Lata and Rhea stay, with a NULL skill name. The same test in `WHERE` would return only Kabir.

### Complete Code

```sql
DROP TABLE IF EXISTS bookings;
DROP TABLE IF EXISTS skills;
DROP TABLE IF EXISTS trainees;
DROP TABLE IF EXISTS rooms;

CREATE TABLE rooms (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    room_name TEXT NOT NULL UNIQUE
);

CREATE TABLE trainees (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name TEXT NOT NULL,
    room_id INTEGER REFERENCES rooms (id)
);

CREATE TABLE skills (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    skill_name TEXT NOT NULL UNIQUE
);

CREATE TABLE bookings (
    trainee_id INTEGER NOT NULL REFERENCES trainees (id),
    skill_id INTEGER NOT NULL REFERENCES skills (id),
    PRIMARY KEY (trainee_id, skill_id)
);

INSERT INTO rooms (room_name)
VALUES
    ('Practice Room A'),
    ('Quiet Room');

INSERT INTO skills (skill_name)
VALUES
    ('Scales'),
    ('Chords'),
    ('Sight Reading');

INSERT INTO trainees (full_name, room_id)
VALUES
    ('Kabir Sen', 1),
    ('Lata Nair', 1),
    ('Rhea Paul', NULL);

INSERT INTO bookings (trainee_id, skill_id)
VALUES
    (1, 1),
    (1, 2),
    (2, 1);

SELECT t.full_name, r.room_name
FROM trainees AS t
INNER JOIN rooms AS r
ON t.room_id = r.id
ORDER BY t.id;

SELECT t.full_name, r.room_name
FROM trainees AS t
LEFT JOIN rooms AS r
ON t.room_id = r.id
ORDER BY t.id;

SELECT t.full_name, s.skill_name
FROM trainees AS t
INNER JOIN bookings AS b
ON t.id = b.trainee_id
INNER JOIN skills AS s
ON b.skill_id = s.id
ORDER BY t.id, s.id;

SELECT t.full_name, s.skill_name
FROM trainees AS t
LEFT JOIN bookings AS b
ON t.id = b.trainee_id AND b.skill_id = 2
LEFT JOIN skills AS s
ON b.skill_id = s.id
ORDER BY t.id;
```

### Alternative approaches

- `ON t.room_id = r.id` can be written as `ON r.id = t.room_id`. The left table is still the one after `FROM`.
- Moving `b.skill_id = 2` into `WHERE` answers a different question. That result is only Kabir Sen.
